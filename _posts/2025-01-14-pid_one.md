As far as I know, there isn't a universally-accepted, robust, practical definition for the word "overhead."

## A unit of work
Computer programs don't spawn in a vacuum and exist as primitive entities within the cosmos.
Each exists for a reason.
To do work.
Why?
Because there is value in having done work.

Let's pretend you've deduced a source of value and created a service which does the corresponding kind of work.
All right, so now you have this box and it is periodically doing a valuable thing.
I think it's informative to pause here.
The _value_ of value is in the exchange--you convert surplus value of one kind for something else.
When you begin to rely on those exchanges, then you rely on the value, and in so doing you reduce the creation of value to--really--an obligation or a bother more than some kind of prize in itself.

This is a new phase!
You are in a situation where someone's obligations are contingent on knowing something about the rate at which this box delivers value and consumes resources.
Uh-oh, the magic box stopped working--if you're going to pause your trip to Maui, you need some mechanism by which to learn that a problem must be solved.
We whacked the magic box ten times harder, but only two times as much money came out--what gives?
You went from nothing to _dependence_ by the mere act of (checks notes) *generating value*.

This is a cheesy setup, to be sure, but think about some of the moving parts here.
I don't know about you, but I was a fully grown adult with a decade of professional experience under my belt before I recognized this relationship.
The _thing_ that creates the value is distinct from the value it creates.
Did you create a better widget-cranker?
Cool!
But don't forget; the value is cranked widgets, not specifically the means by which they are cranked.

In practical terms, what this means in the context of the contemporary zeitgeist is simple.
When you create or improve a thing, and that thing has value, you are obligated to also provide the means by which that value can be _secured_.
Because there are many, _many_, ways in which a computational product can be endangered, and most of those ways can be disarmed or predicted with good leading analysis, you become responsible for observability.

So what do you observe?
